# HiganRTool

<!-- zip:skip -->
[English](./README.en.md)
<!-- /zip:skip -->

東方花映塚（ver.1.50a）用の**非公式**ネット対戦ツールです。

**ZUN氏・上海アリス幻樂団とは関係ありません。自己責任で使用してください。**

Match Modeで使われていない「妖怪 対 妖怪」を間借りして、ゲームの中のメニューからネット対戦・観戦ができるようにします。
adonisやJu.N.Owenと同じく、2人の入力を交換してゲームを同じように進める仕組みです。
さらに、これまでの花映塚のツールには無かったロールバック方式（後述）で、遅延を減らしつつ快適に遊べるようにしています。

## 基本機能

- **ランダムマッチ**: ルーム名を決めずに、同じときにランダムマッチを選んだ人と対戦します。
- **ルームマッチ**: 2人で同じルーム名を入力して対戦します。Ju.N.Owenのルームと同じような使い方です。
- **観戦**: ランダムマッチは一覧から選ぶと、ルームマッチはルーム名を入力すると観戦できます。サーバーを使えないときは、ホストからもらう観戦コードでも観戦できます。観戦は最大10人。途中から入っても、マッチの最初から早送りで追いつきます。
- **接続コード**: ルームが使えないときは、接続コードをDiscordなどで送り合って対戦できます。Ju.N.OwenのPure P2Pと同じような仕組みです。
- **LAN**: 同じLAN内にいる相手と対戦できます。観戦もできます。Radmin VPN・Hamachi・ZeroTierの仮想LANでも使えます。
- **ロールバック方式**: 相手の入力が間に合わないときは予測して進め、外れていたら戻って進め直します。回線が揺れても止まりにくく、adonisより1〜2フレーム（F）ほど低いディレイで遊べます。adonisと同じ、相手の入力を待つdelay方式にも切り替えられます。
- **ディレイの変更**: 試合中でも、Ctrl+数字キーでいつでも変えられます。
- **リプレイの自動保存**: マッチごとに`Replay_HiganRTool\`へ保存します。ファイル名は最初から`th9_udXXXX.rpy`の形です。対戦の情報はリプレイファイルの中に記録するので、ファイルを移動しても失われません。
- **ポート開放はほぼ不要**: 相手探しにはサーバーを使いますが、試合の通信はプレイヤー同士のPCで直接（UDP）行います。ポート開放が要るのは相手がシンメトリックNAT（→「接続できないとき」）のときだけで、ルーターがUPnPに対応していれば自動で開けます。
- **通信の暗号化**: 試合と観戦の通信は、接続するたびに作る使い捨ての鍵で暗号化しています。
- **自動更新**: 起動するたびに新しいバージョンを確かめ、あれば更新します。更新した後は変更点を表示します。変えた設定は引き継ぎます。


## 必要なもの

- Windows（動作確認: Windows 11）
- 東方花映塚（ver.1.50a）
- 相手と連絡を取る手段（Discordなど）


## インストール

1. [Releases](https://github.com/Mako-th/HiganRTool/releases)から最新のzipをダウンロードします。
2. 花映塚のフォルダの**外**に展開します（例: `C:\Games\HiganRTool\`）。
3. `HiganRTool.exe`を起動します。初回だけ花映塚のフォルダを選ぶ画面が出るので、`th09.exe`のあるフォルダを選んでください。
4. 花映塚が起動したら、タイトル→Match Mode→「妖怪 対 妖怪」と進むと、対戦用のメニューが開きます。
5. 最初に、メニューの「プレイヤー名」で名前を決めておきましょう。相手と観戦者に表示されます。

### 置き場所と中身

| ファイル | 中身 |
|---|---|
| HiganRTool.exe | ここから起動します |
| HiganRTool.dll | 花映塚の中で動く本体 |
| HiganRTool.ini | 設定（下の「設定」） |
| HiganRTool_replay_fix.exe | v1.0.0で起こったリプレイのずれを修正するリプレイ修復ツール（下の「仕様」の「リプレイ修復ツール」） |
| README.txt / README_en.txt / LICENSE.txt / THIRD_PARTY_LICENSES.txt | この説明書（日本語・英語）とライセンス |

起動するとこのフォルダに`logs\`（ログ）ができます。


## 起動

2回目からは`HiganRTool.exe`を起動するだけです。
花映塚がもう起動しているときに`HiganRTool.exe`を起動すると、花映塚を2つ目として起動せずにそのまま終了します。
`th09.exe`やvpatchを直接起動すると、このツールは読み込まれません。必ず`HiganRTool.exe`から起動してください。
vpatchは読み込みませんが、フレームの管理はこのツールが代わりに行っており、入力から画面に出るまでの時間はvpatchより短いです。

- 花映塚のフォルダを選び直すときは`HiganRTool.ini`の`[loader]`の`game`の値を消すか、起動の引数に`--choose-game`を付けます。
- 起動できないときは黒いウィンドウに理由が出て止まります。その行を開発者に伝えてください。
- 花映塚を「管理者として実行」にしているときは`HiganRTool.exe`も「管理者として実行」にしてください。


## 更新

起動するたびに更新の確認が入ります（最長約2秒、ネットに接続できなければそのまま起動）。
新しいバージョンがあると「更新しますか？」と出ます。

- **はい**: 起動をやめ、exe・dll・READMEなどを置き換えて、新しいバージョンで起動し直します。置き換えや起動し直しに失敗したときは自動で元のバージョンに戻します。
  - 黒いウィンドウにダウンロードの進み具合が表示されます。
  - 新しいバージョンで最初に起動したときは`HiganRTool.ini`を新しい形に合わせ、変更点を表示します。自分で変えた設定は引き継ぎます（自分で書き足したコメントは残りません）。Enterを押すと花映塚を起動します。`logs`はそのままです。
  - 新しいバージョンにすると困る場合は、更新の前のバージョンに戻せます（花映塚と`HiganRTool.exe`を閉じてから、新しい`HiganRTool.exe`と`HiganRTool.dll`を別の名前に変え、`HiganRTool.exe.old`と`HiganRTool.dll.old`から`.old`を取ります）。`.old`は新しいバージョンで花映塚を起動できた次の起動で消えます。
- **いいえ**: 今のバージョンで起動します。相手とバージョンが違うと接続できません。


## 使い方

### メニュー

↑↓で選び、決定・キャンセルで操作します。パッドでも操作できます。
項目は下の「画面の見方」にあります。
待っている間は、メニューを閉じてほかのモードで遊んでいてかまいません。
待機をやめるときは、メニューの下に出る「待機をやめる」を選びます。
「もどる」でメニューを閉じます。

### ランダムマッチ

ルーム名を決めずに、同じときにランダムマッチを選んだ人と対戦します。

1. メニューの一番上の「ランダムマッチ」を選びます。
2. 相手が見つかると通知音が鳴り、自動で接続します（→「接続した後」）。

待っている間は画面の左上に「ランダムマッチで待機中」と出ます。
**ランダムマッチでは、知らない相手にもグローバルIPアドレスが見えます。** 気になるときは、ルームマッチか接続コードを使ってください。
ランダムマッチは、観戦の「ランダムマッチ」の一覧に載り、誰でも観戦できます（断るときは下の「設定」の「観戦を断る」）。

### ルームマッチ

同じルーム名を入力した2人で対戦します。

1. 相手とルーム名を決めます。ルーム名には英数字と`-` `_` `@`が使用可能で、最大32文字です。ほかの人と重ならない名前にしてください。
2. 2人ともメニューの「ルーム名」に入力してから、対戦の「ルームマッチ」を選びます。
3. 相手がルームに来ると通知音が鳴り、自動で接続します（→「接続した後」）。

待っている間は画面の左上に「ルーム … で待機中」と出ます。
同じルームには2人までしか入れません。

### 接続コード

サーバーを通さずに接続する方法です。ルームのサーバーが応答しないときなどに使ってください。

1. 片方が「対戦コード作成」を選びます。コードがクリップボードにコピーされるので、相手に送ります。
2. 受け取った側は、届いたコードをコピーしてから「対戦コード入力」を選びます。返答コードがクリップボードにコピーされるので、送り返します。
3. 最初の側は、返答コードをコピーしてから「返答コード入力」を選びます。

「接続コード」は、対戦コードと観戦コードをまとめた呼び名です。
コードの有効期限は30分です。
接続コードで接続したマッチは、観戦コードで観戦できます（→「観戦」）。

### LAN

同じLANにいる2人で、サーバーを通さずに対戦します。
オフラインの会場や、LANケーブルでつないだ2台で使用してください。

**ホストの操作**

1. メニューのLANの「ホスト」を選びます。
2. メニューの下に、自分のLANのアドレスとポートが一覧で出ます（4つ以上あるときは↑↓で残りを表示できます）。
3. 相手にそのアドレスを伝え、入力してもらうことで接続が成立します。

**クライアントの操作**

1. メニューのLANの「クライアント」を選びます。
2. ホストのアドレスを入力します。`192.168.0.2:17723`の形で、ポートを省くと17723です。
   前回入力したアドレスが記憶されます。
3. 接続すると通知音が鳴ります（→「接続した後」）。

参加できるのは先着1人です。
ホストが違えば、同じLANで何組でも同時に遊べます（実際の環境では確かめていない、試験的な機能です）。

**注意点**

- ルーターを通さずに直接つないだときは、Windowsがそのネットワークを「パブリック ネットワーク」とみなすことがあります。そのときはファイアウォールの確認で「パブリック ネットワーク」も許可してください（→「困ったとき」）。
- ルーターを通さず2台をLANケーブルで直接つなぐ場合、実際の環境では確かめていませんが、自動で付く`169.254.x.x`のアドレスがホストの画面に出ると思われます。

**VPNの仮想LAN**

Radmin VPN・Hamachi・ZeroTierの仮想LANでも、LANとして対戦・観戦できます。
2人が同じネットワークに入ってから上と同じ手順で接続してください。
ホストの画面では、VPNのアドレスに「26.12.34.56:17723（Radmin）」のようにツールの名前が付きます。
相手には、2人が使っているツールの名前が付いたアドレスを伝えてください。
VPNのツールが中継で接続しているときはその分の遅延が増えます。
WindowsはVPNのネットワークを「パブリック ネットワーク」とみなすことがあります。そのときはファイアウォールの確認で「パブリック ネットワーク」も許可してください（→「困ったとき」）。

### 接続した後

- 2人ともMatch Modeの「妖怪 対 妖怪」を選ぶと、難易度選択に進んで対戦が始まります。ほかのモードで遊んでいたときはキリの良いところで中断するなどして「妖怪 対 妖怪」を選んでください。
- 1P / 2Pは「設定」の「サイド」で決まります。
- 切断するときは、Match Modeや難易度の画面でキャンセル→「はい」です。
- マッチの終わりに「リプレイを保存して終了」を選ぶと、接続を終えます（リプレイは自動で保存済みです）。
- 対戦が終わって接続が切れると、タイトルの「妖怪 対 妖怪」に戻ります。もう一度接続するときは、そこから選んでください。
- 相手からの応答が60秒無いと切断します（相手のゲームが固まったときも、こちらが止まったままにはなりません）。
- 相手の応答が2秒ほど止まると、画面の左上に「相手の応答を待っています」と出ます。その間にEscを3秒長押しすると、自分から切断できます。

### 試合中の操作

- **ディレイを変える**: Ctrl+数字キー（キーボードの上の段）。0〜8はその値、9はautoです。2人とも、いつでも変えられます。
- **同期方式を変える**: キャラ選択の画面でCtrl+Tab。2人とも変えられます。
- **観戦コードをコピーする**: Ctrl+C。2人が接続した後に、ホストが押します。
コピーできたかどうかは、画面の左上に数秒出ます。
- **キャラ・マップのランダム選択と会話のスキップ**: Ctrlか、パッドのスキップボタン（ゲームと同じ）。Ctrl+数字やCtrl+Tabを押したときも、Ctrlを押した扱いになります。どちらか1人が押せば、2人とも会話が飛びます。

### 観戦

ランダムマッチとルームマッチは、それぞれ10人まで観戦できます。
途中から入った場合は、マッチの最初から早送りで追いつきます。
観戦者がいても、2人のマッチの遅延は変わりません。
最後まで観戦したマッチは、観戦した側にもリプレイが保存されます。
観戦をやめるときはEscを押します。
観戦を断るときは、下の「設定」の「観戦を断る」を見てください。

**ランダムマッチ**

1. メニューの観戦の「ランダムマッチ」を選びます。今進行中のランダムマッチが、「1Pの名前 vs 2Pの名前　観戦者の数/上限」で並びます。
2. 観戦したいマッチを選びます（満員のマッチは灰色になります。8件を超えたときは↑↓でスクロールしてください）。
3. 2人のマッチを観戦できます。

**ルームマッチ**

1. 対戦する2人からルーム名を教えてもらいます。
2. メニューの「ルーム名」に入力してから、観戦の「ルームマッチ」を選びます。
3. 2人のマッチが始まると自動で映ります。

ルーム名を知っている人は、誰でも観戦できます。

**観戦コード**

サーバーに接続できないときに使う方法です。

1. 2人が接続したら、ホストがCtrl+Cを押します。観戦コードがクリップボードにコピーされるので、観戦者に送ります。
2. 観戦者は、観戦コードをコピーしてから、メニューの接続コードの「観戦コード入力」を選びます。

ホストは、接続したときの左上の表示に「（ホスト）」と出ている側です。
観戦コードでは、観戦者からホストへ直接届く必要があります。
同じLANにいるか、ホストのUPnPが使えるかを確かめてください。

**LAN**

1. 2人の接続が成立した後、観戦者はメニューのLANの「観戦」を選びます。
2. ホストのアドレスを入力すると観戦できます。

## 設定

- **プレイヤー名**: 相手と観戦者に表示される名前です。試合中は画面の上の左右に出ます。
- **ルーム名**: ルームマッチ（対戦と観戦）で使う名前です。次に起動したときも使われます。
- **サイド**: おまかせ / 1P / 2P。片方がおまかせなら、もう片方の希望に合わせます。希望がぶつかったときと、2人ともおまかせのときはランダムです。
- **同期方式**: rollback（既定） / delay。2人ともrollbackのときだけrollbackになります。
- **ディレイ**: auto / 0F〜8F。autoはpingから自動で決めます（→「仕様」の「ディレイ」）。
- **言語**: 日本語 / English。初めはWindowsの表示言語に合わせます。ログはいつも日本語です。

メニューで変えた設定と選んだ花映塚の場所は、決めた時点でこのツールのフォルダの`HiganRTool.ini`の該当の行に書き込まれます。
`HiganRTool.ini`とメニューはいつも同じ値で、どちらかが優先されることはありません。
メニューに無い設定は、`HiganRTool.ini`を手で書き換えてください。

- **処理を軽くする**: `[pacing]`に`auto_window = b-hybrid`と書くと、処理の重さが約4分の1になります。かわりに遅延がわずかに（約0.2ms）増えます。
  ウィンドウで起動していて配信しながら遊ぶときなど、PCが重いときに試してください。
- **観戦を断る**: 2人とも`[spectate]`の`enable = 0`にします（ホストの値で決まるものがあり、ホストはどちらになるか決まっていないため）。ランダムマッチも一覧に載らなくなります。
- **自動更新を止める**: `[loader]`の`update_check = 0`にします。

**`HiganRTool.ini`の書き方**
- `[replay]`のような行が「カテゴリ」です。その下の`enable = 1`のような「キー = 値」の行が、そのカテゴリの設定です。
  キーは、下の表にあるカテゴリの下に書いてください。
- `;`か`#`で始まる行はコメントアウトされ、使われません。
  配布の`HiganRTool.ini`には`;`を付けてコメントアウトしている行があります。使うときは行の先頭の`;`を消してください。
- 書き換えたら保存してこのツールを起動し直してください。`HiganRTool.ini`は起動したときにだけ読みます。

例: ウィンドウの大きさを1280×960にしたい（配布の`HiganRTool.ini`の最後にある行の`;`を消します）

```
[window]
width = 1280
height = 960
```

知らないキーや読めない値の行は、その行だけ使わず、既定値で動かします。
読めなかった行は、ネット対戦のメニューの下に表示されます（全容はログに出ます）。
行の最後に空白と`;`のあとにコメントを書けます。
UTF-8以外（Shift_JIS）で保存した`HiganRTool.ini`も読めます。

すべての項目は、下の表にあります。

| カテゴリ | キー | 意味 |
|---|---|---|
| [netplay] | name | プレイヤー名 |
| | room | ルーム名 |
| | lan_host | LANの「クライアント」「観戦」で最後に入力したホストのアドレス（`192.168.0.2`か`192.168.0.2:17723`） |
| | mode | 同期方式。`rollback`（既定）/ `delay` |
| | delay | ディレイ。`0`〜`8` / `auto`（既定。rollbackとdelay方式で共通） |
| | host_seat | サイド。`1` / `2`（行が無ければ「おまかせ」） |

## 仕様

**ディレイ（Delay）**
- ディレイ N（画面では「Delay NF」）は、自分の入力をNフレーム（N × 16.7ms）遅らせて、2人が同じフレームで対戦できるようにする処理です。
- autoはpingから決めます。delay方式では往復約33msごとに1F、rollbackでは往復約67msごとに1Fです（rollbackは片道の半分のフレーム数）。pingが小さく安定しているときは0Fです。見直すのはマッチの始まりとCtrl+9を押したときだけで、マッチの途中では変えません。
- マッチごとに揺れないよう、上げるのは往復が境目を5ms超えたとき、下げるのは2マッチ続けて低かったときだけです（Ctrl+9を押したときはすぐ変えます）。

**rollback（既定）**
- 相手の入力がまだ届いていないフレームは「相手は直前と同じ入力」と予測して進め、本物が届いて違っていたら、そのフレームまで戻って進め直します。そのため、待つ方式より低いディレイでも止まらずに遊べます。
- 予測が外れたときは弾や相手が飛んで見えることがあります。
- 2人のゲームの乱数とライフを定期的に比べ、同期ズレが起こったらマッチを止めて通知音を鳴らします。

**delay方式**
- 相手の入力が届くまで待つ方式です（adonisと同じ）。待っている間も画面は止めずに描きます。

**通信**
- 試合の通信はサーバーを通さず、2人のPCの間で直接（UDP）行います。通常ルーターのポート開放は要りません。
- 相手がシンメトリックNATのときだけ、こちらのポートが開いている必要があります。ルーターがUPnPに対応していればこのツールが自動で開けます（→「接続できないとき」）。
- サーバーを使うのは、ルームで相手を探すときと、外から見た自分のアドレスを問い合わせる（STUN）ときだけです。

**リプレイ**
- マッチが終わるたびに1本自動で保存します。保存先は、花映塚のフォルダの`Replay_HiganRTool\<1P> vs <2P>\`です（Program Filesに入れているときはWindowsがVirtualStoreの同じ場所に保存します）。
- 花映塚の`replay`フォルダには書きません。見るときは見たいファイルを`replay`フォルダへコピーしてください。
- 花映塚には、長いマッチのリプレイを保存すると落ちる不具合があります。このツールは保存の前に花映塚が必要な大きさを正しく見積もれるようにしているので落ちません。

**リプレイ修復ツール（HiganRTool_replay_fix.exe）**
- **対象**: v1.0.0とそれより前のバージョンで保存したリプレイです。
  v1.1.0以降で保存したリプレイと、この道具で直したリプレイは、「修正が不要」としてスキップします。
  HiganRToolで保存していないリプレイは直せません。
- **使い方**:
  1. `HiganRTool_replay_fix.exe`をダブルクリックします。
  2. 「リプレイを選ぶ」か「フォルダを選ぶ」で選びます。exeやウィンドウにドラッグ＆ドロップしても選べます。
     フォルダを選ぶと、その中（4段下まで）のリプレイを全部読み込みます。
  3. 1本ずつ、1Pと2Pの名前とリプレイに入っているチャージの設定（slow / charge）が出ます。「前へ」「次へ」で切り替えます。
  4. 「直した後の設定」で、そのマッチで2人が実際に使った設定を選びます。
  5. 「リプレイ単体を修復」で表示中の1本を、「フォルダ全体のリプレイを同様に修復」で同じフォルダのリプレイ全部を、同じ設定で直します。
  6. 終わると何件を処理したか、保存先、スキップしたリプレイが表示されます。
- **保存先**: 元のフォルダの1つ上の`fix_replay\<元のフォルダ名>\<1Pの設定>-<2Pの設定>\`に、同じファイル名で作ります。
  例: `Replay_HiganRTool\Alice vs Bob\th9_ud0008.rpy`を1P charge・2P slowで直すと`Replay_HiganRTool\fix_replay\Alice vs Bob\charge-slow\th9_ud0008.rpy`ができます。
  元のファイルは書き換えません。
  同じ名前のファイルがあるときは上書きしません。
- **設定の選び方**: 自分のPCの設定ではなく、そのマッチで2人が実際に使った設定を選びます。
  どちらか分からないときは2通りで作って、両方を再生して比べてください。
  `Replay_HiganRTool`のフォルダは`<1P> vs <2P>`ごとに分かれていて、同じフォルダの中は1Pと2Pの並びが同じです。
  同じ相手が設定を変えていなければそのフォルダはまとめて直せます。
- **花映塚で見る**: 直したリプレイを花映塚の`replay`フォルダへコピーしてください。
  花映塚での確認や、ずれるリプレイとの入れ換えは、ご自身で行ってください。
- **画面の言語**: 右上の「言語」で日本語 / Englishを切り替えられます。

**このツールが花映塚にすること**
- 花映塚を止めた状態で起動してDLLを読み込ませ、メモリの中の決まった場所だけを書き換えます。書き換える前にそこがver.1.50aの中身どおりかを確かめ、違えば何も書きません。
- 花映塚のフォルダのファイル（exe・設定・セーブ・replay）は書き換えません。書き込むのは`Replay_HiganRTool`の中だけです。
  ネット対戦の間もP・Homeでスクリーンショットを撮れます（保存するのは花映塚自身で、いつもと同じ`snapshot`のフォルダです）。
  自分が押しても、相手のPCでは撮られません。


## 安全性

- **なりすまし**: 試合の通信には全部、接続ごとの秘密の鍵で印（認証タグ）を付けています。接続コードを知らない人が偽の入力や切断を送っても中を読まずに捨てます。
- **中身**: 試合と観戦の通信の中身（入力と名前）は、接続するたびに使い捨ての鍵を作って暗号化しています。ルームのサーバーを動かしている開発者にも読めません。
- **相手に見えるもの**: グローバルIPアドレス（観戦者にはホストのもの）。ランダムマッチは一覧から誰でも観戦できるので、知らない観戦者にも見えます。接続コードにも入っています。信頼できる相手とだけ使い、接続コードやログを知らない人に渡さないでください。
- **ルームのサーバー**: 開発者がCloudflareで動かしています。ルーム名と接続コードを暗号化した通信（HTTPS）で預かって相手に渡すだけで、記録はしません。ただ、接続コードがサーバーを通るので、サーバーが偽のコードを渡して間に割り込むことは、仕組みの上では防げません。気になるときは接続コードを手で送り合ってください。
- **UPnP**: 待機中と試合中だけ家のルーターにbindのポートを開けるよう頼みます（家の中の通信だけです）。
  - 終わったら閉じます。閉じ損ねても1時間で切れます。
  - 期限つきを受け付けないルーターでは期限なしで頼みます。そのときに落ちると「HiganRTool」の名前の割り当てが残りますが、次の起動で引き継いで次回終了時に消します。ルーターの設定画面から手で消してもかまいません。
  - 開いている間はそのポートに外から届きますが、認証タグの合わない通信は捨てます（→「なりすまし」）。使わないときは`HiganRTool.ini`で`upnp = off`です。
- **外への問い合わせ**: 起動するたびに更新の確認を1回（ルームのサーバーと、そこから案内される配布元のGitHub。送るのは問い合わせだけです）。初めて接続するときにSTUN（CloudflareとGoogle）へ1回ずつ。それ以外は、メニューを開かずに遊ぶだけなら通信しません。
- **更新**: 更新ファイルのハッシュ一覧には開発者の署名が付いています。署名が合わない一覧・今より古いバージョン・ハッシュ（SHA-256）が一覧と違うファイルは使いません。

## 接続できないとき

接続できないと左上に原因と番号が出ます。

**シンメトリックNAT**は、通信の相手ごとに外側のポートを変えるルーターのことです（大学・会社のネットワーク、一部の携帯回線に多い）。
この型のルーターの内側からは相手の側のポートが開いていないと接続できません。

1. **原因が分からず、相手からのUDPパケットが届かない**: 下の「ログ」の手順で詳しいログを取ってもう一度試し、2人ともログを添えて、開発者に伝えてください。ネットワークがUDPを通さないときもこの表示になります。
2. **相手がシンメトリックNATで、こちらのUPnPが使えない**: こちらのポートを開けます。どちらか1つをしてください。
   - （a）ルーターの設定画面でUPnPをオンにする（オンにすると家の中のほかのアプリもポートを開けられるようになります）。
   - （b）ルーターでUDPのポート開放（ポートフォワーディング）をして、`HiganRTool.ini`の`bind`をその番号にする。例: `bind = auto:17723`なら、UDP 17723をこのPCへ向けます。使い終わったら閉じてかまいません。
3. **こちらがシンメトリックNAT**: こちら側では直せません。相手に2の（a）か（b）をしてもらってください。相手もシンメトリックNATなら接続できません（4と同じです）。
4. **2人ともシンメトリックNAT**: 直接接続する方法がありません。どちらかが別のネットワーク（家の回線など）から接続してください。
5. **相手から届いているのに接続できない**: 片方の接続コードが古いと片方向にしか届かないことがあります。2人とも「待機をやめる」を選び、片方が新しいコードを作ってすぐ送ってください（ルームマッチ・ランダムマッチなら待機をやめて「接続コード」の「対戦コード作成」に切り替えます）。それでも接続できなければ1と同じようにログを送ってください。


## ログ

- `logs`フォルダに、日ごとに1つのファイル（`dll_YYYYMMDD.log`）で残ります。同じ日に何度起動しても同じファイルに書き足し、起動のたびに「==== 起動 …」の区切りの行が入ります。3日より前のものは自動で消えます。
- 送るのは、その日の`dll_YYYYMMDD.log`だけです（ふだんは簡潔なログで、これ1つです）。
- 起動のときに落ちる・ウィンドウが一瞬で閉じるときは、`logs`の`loader_YYYYMMDD.log`（起動の手順の記録）も添えてください。
- もっと詳しい記録を頼まれたときだけ、`HiganRTool.ini`の`[log]`の`detail = 0`を`detail = 1`に変えて、もう一度遊びます（`[log]`が無い古い`HiganRTool.ini`なら、`[log]`と`detail = 1`の2行を足します）。
  `_net_frames.csv.gz`で終わるファイル（観戦した回は`_watch_frames.csv.gz`）も送ってください。このファイルは起動ごとに別の名前で作られます。`.gz`は開かずにそのまま送ってください。
- ログには名前・Windowsのユーザー名・IPアドレスそのものは書きません（IPは「外」「家の中」などの種類とポート番号だけです）。それでも、送るのは不具合の報告（連絡先は「困ったとき」にあります）にとどめ、誰でも見られる場所にそのまま貼るのは控えてください。


## 現在の制約

- 対応しているのはver.1.50aだけです。
- 2人ともシンメトリックNATのとき、またUDPが通らない回線では接続できません。中継サーバーが必要になるので対応は未定です。
- 中国本土からは、VPNを使わないとルームのサーバー（ランダムマッチ・ルームマッチ・観戦の一覧）に接続できないことがあります。接続コード・LAN・観戦コードはサーバーを使わないので使えます。
  離れた相手とも、Radmin VPN・Hamachi・ZeroTierの仮想LANに2人で入ればLANで対戦できます（→「LAN」）。
- Linux（Wine）で、DLLの読み込みを待つところで時間切れになることがあります。`wineserver -k`を実行してから起動し直してください。
- ほかの花映塚用のツール（対戦ツール・練習ツール）とは同時に使えません（同じ場所を書き換えてぶつかります）。
- リプレイは1つのフォルダに9999本まで保存されます。超えると保存されないので、古いものを移すか消してください。
- v1.0.0で自動保存したリプレイは、2人のチャージの設定（slow / charge）が違うマッチだと、花映塚で再生するとずれます。
  同期方式（rollback / delay）には関係ありません。
  対戦そのものは正しい設定で進んでいて、ずれるのはリプレイの再生だけです。
  v1.1.0から、正しい設定で保存します。
  v1.0.0で保存したリプレイの直し方は、上の「仕様」の「リプレイ修復ツール」にあります。

### ビルド

前提: [Rust](https://rustup.rs/)（`rustup target add i686-pc-windows-msvc`）とVisual Studio Build Tools（リンカとして使います）。
花映塚は32bitなので、32bit向けにビルドします（`.cargo/config.toml`で指定済みです）。

```
cargo build --release
```

`target\i686-pc-windows-msvc\release\`に`higanrtool_loader.exe`（起動用）と`higanrtool.dll`（本体）ができます。
それぞれ`HiganRTool.exe`と`HiganRTool.dll`に名前を変えて、同じフォルダに置いてください。

- 自分でビルドしたものは、配布しているzipとは接続できません（接続の前にビルドの番号を比べています）。自分でビルドしたもの同士は接続できます。
- ルームのサーバー（`src/server`）はCloudflare Workersで動いています。
- ソースの中の検査は、開発用の環境で回しています（検査が読み込むデータの一部は、このリポジトリに入っていません）。
